== AgentOpsとは？

従来のDevOpsは、本番環境でソフトウェアシステムを監視、デバッグ、保守する方法を教えてくれました。しかし、AIエージェントは、非決定的な動作、マルチエージェントのオーケストレーション、LLMの品質のばらつき、分散されたツール呼び出しといった新たな課題をもたらします。

**AgentOps**は、オブザーバビリティ（可観測性）のプラクティスを拡張し、これらの現実に対処します。リクエストの割合やレイテンシを追跡するだけでなく、エージェントの推論パスをトレースし、トークンの消費量を測定し、ツール呼び出しの成功を検証し、出力の品質を継続的に評価する必要があります。

このワークショップでは、その方法を説明します。

== あなたの役割とミッション

あなたは、ローン融資のライフサイクル全体を処理するために洗練されたマルチエージェントAIシステムを導入した住宅ローン融資会社、Fed Aura Capitalのシニアエンジニアです。このシステムは、見込み客からの問い合わせ、借り手の申し込み受け付け、ローン担当者のパイプライン管理、アンダーライターのコンプライアンスチェック、エグゼクティブのアナリティクスという、異なるペルソナにサービスを提供する5つの個別のLangGraphエージェントを使用しています。

CTOから緊急会議が招集されました。「本番環境でAIエージェントに障害が発生しているが、どこで、なぜ発生しているのかわからない。顧客からの苦情は増え、ローン処理時間は予測不能で、これらのマルチエージェントワークフローの内部で何が起こっているのか全く可視化されていない。エンドツーエンドのオブザーバビリティが必要だ。大至急。」

**あなたの任務**: Red Hat OpenShift AIを使用して包括的なAgentOpsオブザーバビリティ戦略を実装し、マルチエージェントシステムの完全な可視性を獲得することです。

**目的**: チームが分散システム障害を診断し、エージェントの意思決定パスを理解し、AIを活用したすべてのワークフロー全体で一貫した品質を確保できるようにする、監視、トレース、および評価機能を確立することです。

== Fed Aura Capitalの課題

**状況**: Fed Aura Capitalは住宅ローンの申し込みを処理するマルチエージェントAIシステムを導入しましたが、複数のエージェントやMCP（Model Context Protocol：AIエージェントを外部ツールやデータソースに接続するための標準規格）ツールにまたがる分散ワークフローの可視性が欠如しています。

**プロジェクトのタイムライン**: 役員会はエンジニアリングチームに対し、オブザーバビリティの向上とインシデント対応時間の短縮を実証するために2週間の猶予を与えました。

**現在の課題** (運用上の問題点):

* **エージェントの相互作用における死角**: ローンの申し込みが失敗した場合、チームは5つのエージェントにまたがるリクエストパスを追跡できず、ログの関連付けを手作業で行うのに何時間も費やすことになります。
* **隠れたレイテンシのボトルネック**: 一部のエージェントが予測不能な遅延を引き起こしていますが、どれが原因かを特定する方法がありません。処理が遅いという顧客からの苦情は増え続けています。
* **MCPツールでのサイレント障害**: 外部ツール呼び出し（コンプライアンスチェック、クレジットスコアリング）がアラートなしで失敗し、数日後に不完全なローンの申し込みが発見されます。
* **品質のベースラインがない**: エージェントが一貫性のある正確な応答を提供しているかどうかを評価する体系的な方法がなく、コンプライアンス違反のリスクが高まっています。

**機会**: Red Hat OpenShift AIは、これらの課題に対処できる統合されたオブザーバビリティスタックを提供します。あなたは、Fed Aura Capitalのユースケースに合わせてそれを評価し、実装する担当者に選ばれました。

**技術的な視点**: 「MLflowのトレース機能とRHOAIのメトリクススタックを組み合わせることで、必要な可視性を得ることができますが、LangGraphエージェントやMCPツールとどのように統合されるかを検証する必要があります。」
