= モジュール 4: トレースと MLflow
:imagesdir: ../assets/images
:navtitle: モジュール 4: トレースと MLflow
:toc: macro
:toclevels: 1

メトリクスは**何が**起きているかを教えてくれますが、トレースは**なぜ**起きているのかを教えてくれます。このモジュールでは、MLflow のトレース機能を使用して、Fed Aura Capital のマルチエージェント住宅ローンシステムにおけるエンドツーエンドの可視性を獲得します。モジュール 1 で行ったリクエストが LangGraph エージェントとツール呼び出しの間でどのように処理されたかをトレースし、あなたが直接体験したオブザーバビリティのギャップを埋めます。

TIP: このモジュールでは、あなたは**両方の役割**を担います：SRE はレイテンシや障害を診断するためにトレースを使用し、AI 開発者はエージェントの推論やツールの動作を理解するためにトレースを使用します。

== 学習目標

このモジュールを修了すると、以下のことができるようになります：

* MLflow UI を操作して、リクエストのトレースを見つけ、分析できる
* トレースをモジュール 1 でのユーザーインタラクションに関連付けることができる
* マルチエージェントの実行タイムライン、ツール呼び出し、および LLM 呼び出しを分析できる
* MLflow がユーザーの ID、入力、出力、およびレイテンシをどのようにキャプチャするかを理解できる

== MLflow トレースの紹介

MLflow トレースは、リクエストの各ステップの入力、出力、およびメタデータをキャプチャする、OpenTelemetry 互換の LLM オブザーバビリティソリューションです。Fed Aura Capital にとって、これはエージェント間のローン申し込みの完全な経路、すべての LLM 呼び出し（プロンプトと応答を含む）、すべてのツール呼び出し、およびエージェントの意思決定ポイントの可視性を意味します。各リクエストは、**スパン**（LLM 呼び出しやツール呼び出しなどの個々の操作）で構成される**トレース**（完全なリクエストフロー）を作成します。これらは、何が何を呼び出したかを示す親子ツリー構造で編成されます。

== トレースはどのように機能するのか？

モジュール 1 で mortgage-ai アプリケーションをデプロイした際、トレースはすでに有効になっていました。手動で設定する必要はありませんでした。すべての LLM 呼び出し、ツール呼び出し、およびエージェントの決定は自動的に記録されました。その仕組みは以下の通りです。

=== MLflow autolog: 1行で設定できるトレース

MLflow トレースは、https://mlflow.org/docs/latest/genai/tracing/integrations/#agent-frameworks-python[40 以上の人気のある LLM および AI エージェントフレームワーク^]と統合されており、**1 行での自動トレース**体験を提供します。アプリケーションの起動時に一度 `autolog()` を呼び出すだけで、すべての LangChain 操作（LLM 呼び出し、ツール呼び出し、エージェントの決定）が自動的にキャプチャされます。エージェントのロジックを変更する必要はありません。

mortgage-ai アプリケーションは https://mlflow.org/docs/latest/genai/tracing/integrations/listing/langchain/[LangChain の自動ログ記録^] を使用しています。https://github.com/rh-ai-quickstart/multi-agent-loan-origination/blob/main/packages/api/src/observability.py#L105[observability.py^] には、トレース設定のすべてが記載されています：

[source,python]
----
import mlflow
import mlflow.langchain

mlflow.set_tracking_uri(settings.MLFLOW_TRACKING_URI)
mlflow.set_experiment(settings.MLFLOW_EXPERIMENT_NAME)
mlflow.langchain.autolog()  # <1>
----
<1> この 1 行により、すべての LangChain および LangGraph 操作の自動トレースが有効になります。エージェント自体のコードを変更することなく、すべての LLM 呼び出し、ツール呼び出し、およびエージェントの決定がスパンとしてキャプチャされます。

MLflow の自動トレースが提供するもの：

* 基本的なオブザーバビリティのための**コード変更はゼロ**: autolog はライブラリレベルでフレームワークにフックします
* **マルチフレームワークアプリ全体での統合されたトレース**: LangChain、LangGraph、およびカスタムツールがすべて 1 つのトレースに表示されます
* 入力、出力、トークン数、モデル名、レイテンシを含む**豊富なメタデータ**
* **本番環境対応のスケーリング**: アプリケーションのブロックを避けるため、トレースは非同期で送信されます

=== OpenTelemetry との互換性

MLflow トレースは、分散トレースの業界標準である https://opentelemetry.io/[OpenTelemetry^] 上に構築されています。つまり、MLflow と並行して、他のバックエンド (Jaeger、Zipkin、Grafana Tempo) にトレースをエクスポートすることもできます。

モジュール 1 で、あなたは **Explore Products** をクリックし、Prospect Agent (プロスペクトエージェント) とチャットしました。その会話は単純なやり取りに見えましたが、MLflow はすべてのステップをキャプチャしていました。そのトレースを見つけてみましょう。

. MLflow の左側のサイドバーで **Experiments** をクリックし、**mortgage-ai** 実験を選択します。これは mortgage-ai アプリケーションによって構成された、すべてのトレースが記録される実験です。

各行には、**Trace ID**、**Request** (ユーザーが尋ねたこと)、**Response** (エージェントが返したもの)、**Execution time** (実行時間)、および **State** (状態) が表示されます。一番下のトレースに注目してください。"What mortgage products do you offer? I'd like..." (どのような住宅ローン製品を提供していますか？ 私は...) というのは、モジュール 1 の Explore Products の会話です。

. そのトレースをクリックして、**Summary** ビューを開きます：
+
image::mlflow3.png[MLflow trace summary showing inputs with user identity and the span sequence of ChatOpenAI and tool calls,link=self,window=blank,width=700]

+
--
* **Inputs (入力)**: エージェントに渡されたユーザーコンテキスト
* **Span sequence (スパンシーケンス)**: 実行された操作 (`ChatOpenAI` の呼び出し、ツール呼び出し、それに続く LLM 呼び出し)
* **Outputs (出力)**: メタデータを含む、ユーザーに返された完全な応答
--

== 演習 3: CEO のトレースをエンドツーエンドで分析する

モジュール 1 の演習 3 を覚えていますか？あなたは CEO の David Park としてサインインし、「ポートフォリオの健全性は？」と尋ね、詳細な応答を得ました。その際、オブザーバビリティのギャップを指摘しました。どのエージェントが質問を処理し、どのツールが呼び出され、各ステップにどれくらいの時間がかかったかを知る術はありませんでした。

今こそ、そのギャップを埋めましょう。

image::mlflow4.png[CEO Executive Dashboard showing the portfolio health question and agent response from Module 1,link=self,window=blank,width=700]

=== CEO のトレースを見つける

. MLflow の **Traces** リストに戻り、_"Show me the current pipeline status"_ ("現在のパイプラインのステータスを表示して") のトレースを見つけます：
+
image::find-trace.png[MLflow Traces list with the pipeline status trace highlighted,link=self,window=blank,width=700]
+
実行時間に注目してください。チャット UI では即座に回答されたように見えた質問の、エンドツーエンドの合計レイテンシです。

=== ユーザー ID のトラッキングを調べる

[start=2]
. トレースをクリックして **Summary** タブを開きます。
+
image::trace-summary.png[MLflow trace summary showing David Park user identity and the span sequence with ChatOpenAI and ceo_pipeline_summary calls,link=self,window=blank,width=700]
+
MLflow は、すべてのトレースで完全なユーザーコンテキストをキャプチャします：
+
--
* **user_id**: `d1a2b3c4-e5f6-7890-abcd-ef1234567804`, 認証されたユーザーの UUID
* **user_email**: `david.park@example.com`, 追跡可能な ID
* **user_name**: `David Park`, CEO のペルソナ
--
+
入力の下にあるスパンシーケンスには、エージェントの実行計画が示されています。`ChatOpenAI` が呼び出され (LLM が何をすべきか決定)、次に `ceo_pipeline_summary` が呼び出され (ツールがデータをフェッチ)、その後再び `ChatOpenAI` が呼び出されました (LLM が応答を作成)。
+
NOTE: スパンシーケンスにツール呼び出し (例: `ceo_pipeline_summary`) が表示されない場合は、Mortgage AI App に戻り、同じ質問をもう一度してください。LLM は非決定的です。最適化されたシステムプロンプトを使用しても、モデルがツールを呼び出さずにトレーニングデータから回答することがあります。ツール呼び出しを含むトレースが表示されるまで繰り返し、その後次のステップに進んでください。

=== 実行タイムラインの探索

[start=3]
. **Details & Timeline** タブをクリックし、**Show execution timeline** をクリックして、トレースの完全な内訳を確認します：
+
image::nav-execution-timeline.png[MLflow Details and Timeline view showing the full execution tree from LangGraph through input shield agent ChatOpenAI tool calls and output shield,link=self,window=blank,width=700]
+
トレースツリーは完全な実行パスを示しています：`LangGraph` → `input_shield` → `agent` → `ChatOpenAI` (1.26秒、ツールを呼び出すことを決定) → `tool_auth` → `ceo_pipeline_summary` (17ms、パイプラインデータをフェッチ) → `agent` → `ChatOpenAI` (6.44秒、応答を作成) → `output_shield`。これで、モジュール 1 のオブザーバビリティの課題からのすべての質問に答えることができます。
+
[%collapsible]
.スパンの完全な内訳 (クリックして展開)
====
[cols="1,2",options="header"]
|===
|スパン |機能

|`LangGraph`
|ルートオーケストレーター: エージェントワークフロー全体を管理します

|`input_shield`
|安全フィルター: 入力に有害なコンテンツがないかチェックします

|`agent` (1回目)
|LangGraph エージェントノード: LLM にルーティングします

|`ChatOpenAI` (1回目)
|LLM 呼び出し: `ceo_pipeline_summary` ツールを呼び出すことを決定します

|`should_continue`
|意思決定ポイント: エージェントは処理を継続すべきか？

|`tool_auth`
|承認チェック: CEO ロールはこのツールへのアクセス権を持っているか？

|`tools` → `ceo_pipeline_summary`
|ツール実行: データベースにクエリを実行してパイプラインデータを取得します

|`agent` (2回目)
|LangGraph エージェントノード: ツールの結果を LLM にルーティングします

|`ChatOpenAI` (2回目)
|LLM 呼び出し: 生のパイプラインデータから自然言語の応答を作成します

|`output_shield`
|安全フィルター: ユーザーに返す前に出力をチェックします
|===
====

=== ツール呼び出しを検査する

[start=4]
. トレースツリーで、**ceo_pipeline_summary** スパンをクリックして、ツールの入力と出力を確認します：
+
image::mlflow7.png[MLflow span detail for ceo_pipeline_summary showing input days=90 and output with pipeline summary data,link=self,window=blank,width=700]
+
--
* **Inputs (入力)**: `days: 90`, ツールは 90 日間のパイプラインデータをクエリします
* **Outputs (出力)**: `"Pipeline Summary (90-day window): Total active applications: 38..."`, LLM が応答を作成するために使用した生のデータ
--
+
これがエージェントが数字を取得した場所です。CEO の応答に不正確なデータが含まれていた場合、このツールの出力まで直接トレースし、問題がツールのロジックにあるのか LLM の解釈にあるのかを検証できます。

=== LLM 呼び出しを検査する

[start=5]
. 最後の **ChatOpenAI** スパンをクリックして、実際の LLM 呼び出しを確認します：
+
image::mlflow8.png[MLflow span detail for ChatOpenAI showing model nvidia/nemotron-3-nano with system prompt and completion,link=self,window=blank,width=700]
+
--
* **Model (モデル)**: `nvidia/nemotron-3-nano`, このリクエストを処理している正確なモデル
* **Inputs → messages**: システムプロンプト (_"あなたは Fed Aura Capital のエグゼクティブアシスタントです"_) と、ツールの結果を含む会話のコンテキスト
* **Outputs → choices**: 安全フィルターやフォーマット処理前の、完全な LLM の応答
--
+
このレベルの詳細はデバッグに不可欠です。モデルが受け取った正確なプロンプト、それを処理したモデルのバージョン、安全フィルターやフォーマット処理の前の生のコンプリーション (生成結果) を確認できます。

== 演習 4: ユーザーセッションの探索

実際の多くの AI アプリケーションは、複数回のユーザーインタラクションを維持するためにセッションを使用します。https://mlflow.org/docs/latest/genai/tracing/track-users-sessions/[MLflow トレースは、トレースをユーザーに関連付け、それらをセッションにグループ化するための組み込みのサポート^]を提供します。LLM アプリケーションまたは AI エージェントでユーザーとセッションを追跡することは、ユーザーの行動を理解し、会話フローを分析し、パーソナライゼーションを改善するための重要なコンテキストを提供します。

. MLflow の左側のサイドバーで、**Observability** の配下にある **Sessions** をクリックします：
+
image::sessions0.png[MLflow left sidebar showing Sessions under Observability,link=self,window=blank,width=700]

. mortgage-ai アプリケーションでは、各チャット会話が 1 つのセッションとして追跡されます。MLflow はセッション内のすべてのターンをグループ化し、完全な会話フローを確認できるようにします：

image::sessions1.png[MLflow Chat Sessions view showing a session with 7 turns grouped by user and agent,link=self,window=blank,width=700]

セッションをクリックすると、入力と出力を含む各ターンが表示されます。任意のターンで **View full trace** をクリックすると、詳細なトレースビューに直接ジャンプできます：

image::sessions2.png[MLflow session detail showing Turn 1 with inputs outputs and View full trace link,link=self,window=blank,width=700]

これは、時間の経過とともにエージェントの動作が劣化するような複数ターンの会話をデバッグする際に特に役立ちます。エージェントが各ステップで持っていた完全なコンテキストを確認できます。

== モジュールのまとめ

**達成したこと:**

* MLflow にアクセスし、モジュール 1 のインタラクションからのトレースを見つけました
* CEO のトレースをエンドツーエンドで分析しました（入力シールド、LLM 呼び出し、ツール承認、ツール実行、および出力シールド）
* 個々のスパンを検査して、ツールの入力/出力と LLM のプロンプト/コンプリーションを確認しました

**重要なポイント:**

* MLflow autolog は、コードの変更なしでエンドツーエンドのトレースを提供します (1 行で有効になります)
* トレースはユーザー ID、実行タイムライン、ツール/LLM の詳細をキャプチャし、マルチエージェントシステムのオブザーバビリティのギャップを埋めます
* 個々のスパンを検査することで、問題の原因を特定のコンポーネント（ツールのロジック、LLM のプロンプト、または安全フィルター）に特定できます

**次のステップ:**

これでコアとなるオブザーバビリティモジュールは完了です！メトリクス、トレース、およびログが連携して、マルチエージェントシステムを監視するようになりました。
