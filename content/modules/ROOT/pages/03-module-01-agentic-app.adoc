= Module 1: The agentic app and why observability matters
:navtitle: Module 1: The Agentic App
:source-highlighter: rouge
:toc: macro
:toclevels: 1

Agentic AI apps don't fail silently -- they fail distributedly. In this module, you'll deploy and explore the mortgage-ai multi-agent application and understand why traditional monitoring approaches fall short for these complex systems.

Fed Aura Capital needs end-to-end visibility into their multi-agent workflows, and you've been tasked with evaluating how observability can help. Before implementing solutions, you need to understand what you're working with.

In this module, you'll experience firsthand why multi-agent systems require a different approach to observability.

== Learning objectives

By the end of this module, you'll be able to:

* Deploy the mortgage-ai multi-agent system using Helm
* Describe the architecture of the multi-agent mortgage lending system
* Identify the five distinct agent personas and their responsibilities
* Explain why distributed AI systems require specialized observability approaches
* Recognize the key failure modes in multi-agent architectures

== Exercise 1: Deploy the mortgage-ai application

The mortgage-ai multi-agent system is packaged as a Helm chart. Let's deploy it to your namespace.

. First, log in to OpenShift:
+
[source,bash]
----
oc login {openshift_api_url} -u {user} -p {password}
----

. Create and switch to your workspace namespace:
+
[source,bash]
----
oc new-project wksp-{user} || oc project wksp-{user}
----

. Clone the multi-agent loan origination repository:
+
[source,bash]
----
git clone https://github.com/rh-ai-quickstart/multi-agent-loan-origination.git
cd multi-agent-loan-origination
----

. Export the Helm chart variables for your deployment:
+
[source,bash]
----
export LLM_BASE_URL="https://llm-gateway.apps.<cluster-domain>/v1"
export LLM_API_KEY="ToBeFilled"
export LLM_MODEL="qwen3-14b"
export COMPANY_NAME="Fed Aura Capital"
export MLFLOW_TRACKING_URI="https://mlflow.apps.<cluster-domain>/mlflow"
export MLFLOW_WORKSPACE="wksp-{user}"
export MLFLOW_EXPERIMENT_NAME="wksp-{user}"
----

. Deploy the application using Helm:
+
[source,bash]
----
helm install mortgage-ai ./deploy/helm/mortgage-ai \
  -n mortgage-ai --create-namespace \
  --set secrets.LLM_BASE_URL="${LLM_BASE_URL}" \
  --set secrets.LLM_API_KEY="${LLM_API_KEY}" \
  --set secrets.LLM_MODEL="${LLM_MODEL}" \
  --set secrets.COMPANY_NAME="${COMPANY_NAME}" \
  --set secrets.AUTH_DISABLED=true \
  --set keycloak.enabled=false \
  --set secrets.MLFLOW_TRACKING_URI="${MLFLOW_TRACKING_URI}" \
  --set secrets.MLFLOW_EXPERIMENT_NAME="${MLFLOW_EXPERIMENT_NAME}" \
  --set secrets.MLFLOW_WORKSPACE="${MLFLOW_WORKSPACE}" \
  --set secrets.MLFLOW_TRACKING_INSECURE_TLS=true \
  --set mlflow.rbac.enabled=true \
  --set seed.enabled=true
----

. Wait for all deployments to become ready:
+
[source,bash]
----
oc rollout status deployment/mortgage-ai-api -n wksp-{user}
oc rollout status deployment/mortgage-ai-ui -n wksp-{user}
----

=== Key AI patterns

This application demonstrates production-ready AI patterns for regulated industries:

* **Multi-agent orchestration** - Five LangGraph agents with role-scoped tools and RBAC enforcement
* **Compliance knowledge base** - pgvector RAG with tiered boosting (federal regulations > agency guidelines > internal policies)
* **Model routing** - Complexity-based routing between fast and capable LLM tiers
* **Comprehensive audit trail** - Hash-chained, append-only audit events with MLflow trace correlation
* **PII masking** - Middleware-based masking for executive roles (SSN, DOB, account numbers)
* **Safety shields** - Input and output content filters with escalation pattern detection

== Exercise 4: Experience the observability gap

Now that you understand the five agent personas and how they collaborate, let's experience firsthand the observability challenge that comes with distributed AI systems.

You'll interact with the application as a CEO and ask the assistant a question. The response will look correct -- but you'll have no way of knowing what happened behind the scenes.

. From the application landing page, click **Sign In**. In the sign-in dialog, use the **Persona Demo Login** section at the bottom and select the **CEO** persona:

=== The observability challenge

The response looks great. But stop and think about what just happened behind the scenes:

* Which **agent** processed your question? Was it a single agent, or did multiple agents collaborate?
* Which **tools** did the agent invoke to gather pipeline data, denial rates, and performance metrics?
* How **long** did each step take? Was the LLM call fast, or did a tool call add latency?
* What if the response was **wrong** -- how would you trace back to the root cause?
* What if a tool call **failed silently** -- would you even know?

Without proper observability instrumentation, these questions are unanswerable. The application gives you a polished response, but the entire decision-making process -- the agent routing, tool invocations, LLM calls, and data retrieval -- remains a black box.
