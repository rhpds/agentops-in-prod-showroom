== Key metrics for agentic applications

Before building dashboards, let's define what we need to measure. Agentic AI systems require metrics beyond traditional application monitoring.

=== Infrastructure metrics (SRE focus)

[cols="2,3,2",options="header"]
|===
|Metric |Description |Why It Matters

|Pod CPU/Memory
|Resource utilization per agent pod
|Capacity planning, cost optimization

|Request Rate
|Requests per second to each agent
|Load understanding, scaling decisions

|Error Rate
|Percentage of failed requests
|System health, SLO tracking

|Latency (P50, P95, P99)
|Response time distribution
|Performance monitoring, SLO compliance
|===

=== AI-specific metrics (AI Developer focus)

[cols="2,3,2",options="header"]
|===
|Metric |Description |Why It Matters

|Token Usage
|Input/output tokens per request
|Cost management, model efficiency

|Inference Latency
|Time spent in LLM inference
|User experience, bottleneck identification

|Agent Handoff Rate
|Frequency of agent-to-agent transfers
|Workflow efficiency, routing optimization

|MCP Tool Success Rate
|Success/failure rate of external tool calls
|Integration health, reliability

|Confidence Scores
|Agent decision confidence distribution
|Quality assurance, model performance
|===

=== Business KPIs (Executive focus)

[cols="2,3,2",options="header"]
|===
|Metric |Description |Why It Matters

|Loan Processing Time
|End-to-end time from inquiry to decision
|Customer experience, operational efficiency

|Compliance Check Pass Rate
|Percentage of applications passing compliance
|Risk management, regulatory adherence

|Agent Automation Rate
|Requests handled without human intervention
|ROI, automation effectiveness
|===

== Exercise 2: Access and configure Grafana

Now let's set up Grafana for custom dashboards that go beyond the built-in RHOAI monitoring.

. Check if Grafana is already deployed:
+
[source,bash]
----
oc get pods -n grafana-operator
oc get route -n grafana-operator
----

. If Grafana is not deployed, deploy it:
+
[source,bash]
----
# Create namespace for Grafana
oc new-project grafana-dashboards

# Deploy Grafana operator
cat << 'EOF' | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: grafana-operator
  namespace: openshift-operators
spec:
  channel: v5
  name: grafana-operator
  source: community-operators
  sourceNamespace: openshift-marketplace
EOF
----

. Wait for the operator to be ready:
+
[source,bash]
----
oc wait --for=condition=Ready pod -l control-plane=controller-manager -n openshift-operators --timeout=120s
----

. Deploy a Grafana instance:
+
[source,bash]
----
cat << 'EOF' | oc apply -f -
apiVersion: grafana.integreatly.org/v1beta1
kind: Grafana
metadata:
  name: acme-fintech-grafana
  namespace: grafana-dashboards
spec:
  config:
    auth:
      disable_login_form: false
    security:
      admin_user: admin
      admin_password: admin123
EOF
----

. Get the Grafana route:
+
[source,bash]
----
oc get route -n grafana-dashboards acme-fintech-grafana-route -o jsonpath='{.spec.host}'
----

=== Verify

Confirm Grafana is accessible:

GRAFANA_ROUTE=$(oc get route -n grafana-dashboards acme-fintech-grafana-route -o jsonpath='{.spec.host}')

== Exercise 3: Build an agent metrics dashboard

Now let's create a custom dashboard for monitoring the Acme FinTech multi-agent system.

. First, configure Prometheus as a data source in Grafana:
+
[source,bash]
----
cat << 'EOF' | oc apply -f -
apiVersion: grafana.integreatly.org/v1beta1
kind: GrafanaDatasource
metadata:
  name: prometheus-datasource
  namespace: grafana-dashboards
spec:
  instanceSelector:
    matchLabels:
      dashboards: acme-fintech
  datasource:
    name: Prometheus
    type: prometheus
    access: proxy
    url: https://thanos-querier.openshift-monitoring.svc.cluster.local:9091
    isDefault: true
    jsonData:
      httpHeaderName1: Authorization
      tlsSkipVerify: true
    secureJsonData:
      httpHeaderValue1: "Bearer ${PROMETHEUS_TOKEN}"
EOF
----

. Create the AgentOps dashboard:
+
[source,bash]
----
cat << 'EOF' | oc apply -f -

== Exercise 4: Create alerts for agent health

Now let's configure alerts that notify the SRE team when agent health degrades.

. Create a PrometheusRule for agent alerts:
+
[source,bash]
----
cat << 'EOF' | oc apply -f -
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: agentops-alerts
  namespace: acme-fintech-agents
spec:
  groups:
  - name: agent-health
    rules:
    - alert: AgentHighErrorRate
      expr: |
        sum(rate(http_requests_total{namespace="acme-fintech-agents", status=~"5.."}[5m]))
        / sum(rate(http_requests_total{namespace="acme-fintech-agents"}[5m])) > 0.05
      for: 2m
      labels:
        severity: warning
      annotations:
        summary: "High error rate detected in agent services"
        description: "Error rate is above 5% for more than 2 minutes"

    - alert: AgentHighLatency
      expr: |
        histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket{namespace="acme-fintech-agents"}[5m])) by (le)) > 5
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "High latency detected in agent services"
        description: "P95 latency is above 5 seconds for more than 5 minutes"

    - alert: MCPToolFailures
      expr: |
        sum(rate(mcp_tool_calls_total{status="error"}[5m])) > 0.1
      for: 3m
      labels:
        severity: critical
      annotations:
        summary: "MCP tool calls are failing"
        description: "MCP tool error rate is elevated for more than 3 minutes"
EOF
----

. Verify the alerts are registered:
+
[source,bash]
----
oc get prometheusrule -n acme-fintech-agents
----

. Check the alert status in the OpenShift console:
+
--
Navigate to **Observe** → **Alerting** → **Alerting rules** and filter by `acme-fintech-agents`.
--

=== Verify

Confirm alerts are configured:

[source,bash]
----

----

Expected output: `AgentHighErrorRate AgentHighLatency MCPToolFailures`

== Troubleshooting

**Issue**: Grafana dashboard shows "No data"
**Solution**:

. Verify Prometheus data source is configured correctly
. Check if metrics are being scraped: query `up{namespace="acme-fintech-agents"}` in Prometheus
. Ensure ServiceMonitor is deployed for agent services
. Check time range in Grafana (try "Last 1 hour")

**Issue**: Cannot connect Grafana to Prometheus
**Solution**:

. Verify the Prometheus URL is correct
. Check network policies allow traffic from Grafana namespace
. Ensure bearer token has correct permissions
. Try using the internal service URL instead of route

**Issue**: Alerts not firing when expected
**Solution**:

. Verify PrometheusRule is in the correct namespace
. Check if the metrics referenced in alert expressions exist
. Review alert thresholds -- they may be too high
. Check Prometheus UI for alert rule evaluation status

**Issue**: GrafanaDashboard not appearing
**Solution**:

. Verify instanceSelector matches the Grafana instance labels
. Check GrafanaDashboard status: `oc describe grafanadashboard <name>`
. Review Grafana operator logs for errors
